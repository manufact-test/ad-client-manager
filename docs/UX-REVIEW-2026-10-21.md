## Реализовано и проверено кодом/CI

- Единая ширина и вертикальная сетка. Шапка без названия продукта; вкладки в шапке; имя, роль и выход справа, компактная прокрутка меню на узком экране.
- Фиолетовый фокус вместо оранжевого, более заметная иконка встроенного календаря, стилизованная стрелка select, обновлённые контролы. **Сам popup нативного календаря/выпадающего списка зависит от Chrome/ОС; кастомный полностью управляемый календарь не внедрялся.**
- Упрощены настройки: пароль и импорт CSV раскрываются по запросу; роли локализованы; сотрудники в списке, ввод нового сотрудника не должен подставлять текущие данные через стандартные autocomplete поля.
- В «Клиентах» убраны пояснения про демо, пустой блок «рабочих напоминаний», технический хлам. Автоматические напоминания НЕ создавали личные задачи; их общий UI скрыт, расчётная функция в коде оставлена для будущего размещения **в контексте клиента** после UX-согласования.
- В форме клиента поле «Рекламные системы» заменено на «Что делаем для клиента»; «Другое» раскрывает поле уточнения источника; прежних клиентов теперь можно выбирать из всего списка. Повторное обращение — отдельная секция. Валюты: BYN, RUB, EUR, USD, KZT. Расчётный день нового сотрудничества берётся из дня даты начала, исторические явные значения допускаются сервером для совместимости.
- Карточка клиента: сначала обзор данных, финансовые показатели, ссылки на периоды/документы; редактирование карточки свёрнуто и вынесено к низу. Понятные названия основных действий, русские категории начислений, последний активный период раскрыт.
- «Мои задачи»: отдельные карточки месяцев; внутри — явные дни и компактные задания; редактирование выбранной задачи **на месте**, одинаковые кнопки действий и компактная форма создания. Формат даты в интерфейсе `ДД.ММ.ГГГГ`, ежемесячный перенос сохранён.
- Для HTTP 500 аналитики переписан сомнительный для разных MySQL/MariaDB запрос агрегатов с коррелированными подзапросами; CI дополнен сценарием отображения аналитики при только демо-клиентах. **Работа реальной страницы под сессией на Hostinger пока не проверена.**
- Удалены прямые технические идентификаторы событий из журнала; англоязычные категории и роли заменены пользовательскими. Импорт CSV скрыт под отдельную секцию без разработческих заметок.
- Исправлены E2E проверки только в местах, где интерфейс намеренно изменил тексты/формат дат. Контроль финансовых сумм, доступа ролей, конфликтов старой вкладки и PDF сохранён. Финальный CI SUCCESS.

## Что осталось проверить глазами после автодеплоя

1. Шапку, общее выравнивание и отсутствие горизонтального выпадения во всех пяти вкладках.
2. Настройки: раскрытие секций, пустые поля нового сотрудника, отсутствие оранжевого фокуса, русский журнал.
3. Аналитика: вместо HTTP 500 полноценная страница под директором даже если есть только демонстрационный клиент.
4. Задачи: месяц/день/сегодня, редактирование задачи прямо на месте, встроенный календарь на компьютере и телефоне.
5. Создание клиента: начало сотрудничества, источник «Другое», повторное обращение, выбор валюты, ввод стоимости.
6. Карточка клиента: читаемость обзора, вкладки-якоря, документы, финансы, период, скрытая правка.
7. Скорость переключения: проверить на реальном сервере, поскольку полная смена страниц всё ещё зависит от Hostinger/PHP/сети. **Мгновенность переключения пока не доказана.**

## Важные границы

- `quoted_amount` в БД остаётся **стоимостью по договору**, а не создаваемым автоматически начислением. Финансовые начисления по-прежнему добавляются отдельно по периодам. Это надо согласовать в функциональной приёмке, чтобы не спутать стоимость с фактически выставленной оплатой.
- Автоматическая логика напоминаний **не удалена**, показ общего списка скрыт по UX-запросу. Возможное возвращение событий только с ясным контекстом внутри конкретного клиента.
- Не менялись схема MySQL, хранимые PDF, реальные клиентские записи, `main`, PR #2. Основной PR остаётся **OPEN DRAFT, не сливать**.
- Резервная копия Hostinger создана владельцем, её SQL+PDF состав и независимое восстановление ещё не подтверждены. Полная ручная финансовая приёмка, перевод GitHub PUBLIC→PRIVATE и реальный release остаются обязательными.
