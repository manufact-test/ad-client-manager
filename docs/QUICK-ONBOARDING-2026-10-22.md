# Ad Client Manager — массовое добавление клиентских карточек из CSV

Дата: 22.10.2026. Этап **быстрого переноса клиентской базы** на будущий безопасно выпущенный тестовый сайт. Ветка `feature/integrated-client-workflow`, PR #2 OPEN DRAFT, `main`/`deploy`/Hostinger не изменяются. Пока репозиторий GitHub PUBLIC, **на тестовом сайте применять только вымышленные данные** и не публиковать настоящие клиентские SQL/PDF/CSV в GitHub.

## Для кого и зачем

Директор вместо последовательного создания десятков карточек может заполнить один простой CSV. **Каждая строка — одна новая карточка клиента и первое активное сотрудничество**. Импорт не порождает счета, документы, начисления, «получено», задачи или исторические финансовые строки. Заполненная сумма `quoted_amount` — справочная ежемесячная сумма договора, **не долг и не платеж**. Отдельный 18-колоночный исторический импорт сохранён для прошлых оплат и периодов и не заменён этим механизмом.

Открыть **«Клиенты» → «Массово добавить клиентов из CSV»** или **«Настройки» → «Массовое добавление клиентов — быстрый CSV»**. Нажать **«Скачать шаблон CSV»** (авторизованный URL `/?export=quick_clients_template` доступен только директору). Заполнить строки в Excel / LibreOffice / Google Sheets, затем **сохранить CSV UTF-8, разделитель запятая**.

### Колонки шаблона и значения

| Поле | Правило |
|---|---|
| `client_name` | Название клиента, обязательно, до 240 символов |
| `is_demo` | `0` реальный, `1` демонстрационный |
| `started_on` | Дата первого сотрудничества `YYYY-MM-DD`, расчётный день автоматически берётся из числа даты |
| `payment_mode` | `prepayment` или `postpayment` |
| `currency` | BYN, RUB, EUR, USD или KZT — те же валюты, что и в обычной форме |
| `quoted_amount` | Ежемесячная справочная сумма, `1250.00`; пусто = неизвестна (legacy DB хранит 0.00, но начисления не создаются) |
| `legal_type` | `legal` или `individual` |
| `source_kind` | `advertising`, `referral`, `old_contact`, `inbound`, `other` |
| `platform_text` | Что делаем для клиента (до 400 символов) |
| `source_note` | Дополнительный источник (до 240 символов), необязательно |
| `previous_name_text` | Прежнее название повторного клиента (до 240), без автоматического связывания с другим ID |
| `requires_acts` | `0` или `1`, нужен ли акт |
| `requires_specs` | `0` или `1`, нужна ли спецификация |
| `comment_text` | Примечание до 5000 символов |

CSV-заголовок должен совпадать с шаблоном **буква в букву и в том же порядке**. Не удаляйте пустые колонки. Объём до **2 МБ и 500 клиентов** за одну загрузку. Не надо смешивать старые финансовые операции с этим шаблоном.

## Два безопасных шага

1. **«Проверить перед импортом»**. Сервер полностью проверяет все строки и наличие дублей среди уже заведённых клиентов. Ничего не пишет в базу. На экране — число реальных/демо-клиентов и первые восемь имён для проверки.
2. **«Подтвердить добавление»**. Повторно выбрать **точно тот же файл**. Сервер сверяет SHA-256 с предпросмотром, повторно проверяет дубли внутри защищённой транзакции, создаёт все карточки и первые сотрудничества одним действием. При ошибке **ни один клиент из пачки не добавляется**. В журнал записывается агрегат без личных данных и хеш файла, сам CSV нигде не хранится.

Защиты: доступ только директору после входа/смены временного пароля, CSRF на POST, загрузка только реально полученного временного файла, проверка UTF-8/формата/дат/валют/сумм, предупреждение о дублях (одинаковое имя + один тип demo), транзакция + общий advisory lock импорта, защита повторного SHA. Одновременный **ручной** ввод карточки сотрудником технически может состязаться с CSV (для полного глобального уникального ограничения потребовалось бы изменение схемы, которого пока нет); поэтому во время массового импорта попросите сотрудников не заводить новых клиентов вручную. Штатно повторные клиенты с тем же названием корректируются в существующих карточках, а не дублируются.

## Приёмка на тестовых клиентах — Q1–Q4 PENDING

Q1 — директор скачивает UTF-8 CSV; сотрудник получает HTTP 403, незалогиненный — страницу входа. Проверка CSV из двух строк не меняет базу и выводит числа.

Q2 — повторная загрузка *того же* CSV за одно подтверждение создаёт обе карточки и их договоры. Проверить расчётный день, валюту, справочную сумму, необходимые акт/спецификацию, комментарий, demo-изоляцию. Нет новых charge_lines, payment_events, client_entries или PDF.

Q3 — повтор этого же файла и другой CSV с одним существующим клиентом и одним новым отклоняются; новый не появляется. Ошибка во второй строке не оставляет первого клиента. Изменённый после предпросмотра файл не принимается.

Q4 — обычная карточка по-прежнему работает, отдельный исторический CSV продолжает работать, разрешения сотрудника/аудит соблюдаются. Посмотреть поведение на мобильном экране и в Chrome/Edge.

**Q1–Q4 вручную НЕ пройдены.** Реальные клиенты допускаются только после восстановления SQL+PDF на независимом Hostinger, проверки UI, перевода GitHub в PRIVATE с аудитом истории и отдельного выпуска. Пройти их не означает, что Gate B/C/D автоматически закрыты.
