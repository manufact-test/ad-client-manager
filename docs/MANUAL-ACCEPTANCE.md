## 22.10.2026 — полная переработка финансов и UX (последняя контрольная точка)

Это актуальнее разделов ниже. Рабочая ветка feature/integrated-client-workflow, PR #2 OPEN DRAFT, main не тронут. Предыдущие финансовые таблицы остаются историческими — их нельзя стирать. Репозиторий PUBLIC, до реальных данных сделать PRIVATE.

- **Одна запись — один документ/запрос и одна сумма.** В форме загрузки PDF необязательна галочка «Указать сумму к оплате». Несколько типов одного PDF не умножают сумму. Галочка «Оплата на карту» создаёт запись без обязательного PDF; валюта, сумма, категория и комментарий берутся из этой записи.
- **Действия по каждому месяцу.** Неотправленные и неоплаченные строки всегда открыты. Сотрудник отмечает «Отправили» у PDF и «Получили» у каждого документа по отдельности. Оплаченные автоматически свернуты, раскрываются стрелкой. «Отменить получение» возвращает неоплаченное состояние и пересчитывает аналитику; удаление документа удаляет связанную с ним сумму, исправление документа меняет ту же запись, не создавая дубликата.
- **Статусы — общий список клиентов.** «Отправить документы» приоритетнее «Подготовить документы» и «Ждём оплату». После подтверждённого получения: «Оплачено». Все сотрудники видят общий статус; личные задачи не дублируются. График подготовки подсчитывается от договорного дня с допуском ±3 дня, сумма никогда не начисляется по шаблону автоматически.
- **История условий.** «Добавить новые условия» создаёт запись engagement_terms, прежние версии сохраняются. Текущая дата и условия отображаются в «О клиенте». Ручной пункт добавления расчётного периода убран из UI. Поле месячной стоимости из создания новых условий убрано; старые ненулевые ориентиры отображаются отдельно.
- **Карточка и дизайн.** «Выгрузить историю в CSV» справа от заголовка «О клиенте», затем единый блок «Документы и оплаты» с кнопками Изменить/Удалить. Демо удаляется только директором. Таблица клиентов со статусом и зеброй, кнопка открыть справа, кастомные фиолетовые списки и календарь.
- **Аналитика.** Новые суммы учитываются в агрегатах, LTV и CSV, оплачено только после кнопки «Получили». Вся отмена/удаление пересчитывает итоги. Демо исключены из глобальных финансов, клиентский CSV содержит и актуальную, и аннулированную историю. Старые charge_lines и payment_events остаются доступными для исторической отчётности.
- **Схема БД.** Добавлены client_entries и engagement_terms, существующие PDF при миграции связываются с пустыми по сумме записями. Миграция ТОЛЬКО после резервной копии MySQL и приватных PDF, явным действием директора на выделенном Hostinger staging. Не выполнять DDL автоматически при каждом входе.
- **Автоматические проверки.** PHP lint, MySQL, HTTP E2E для отправки документа, независимых месяцев, исправления без второго PDF, ошибочной оплаты и её отмены, карточной оплаты без PDF, роли, CSV, демо-исключения; плюс security и restore fixtures. Отдельно нужна ручная UI-приёмка на Hostinger после тестовой выкладки.
- **Release gates:** SQL+PDF restore, UI/UX приёмка, GitHub PRIVATE, проверка выпуска. Успешный CI не заменяет эти проверки.
