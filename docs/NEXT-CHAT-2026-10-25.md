## Что владелец просил исправить / проверить

### 1. Карточка клиента и таблица клиентов

- В таблице заголовок «Как оплачивают» должен быть выровнен по левому краю, как содержимое колонки.
- В карточке клиента «Как оплачивают» находится в конце блока «О клиенте»; маленький карандаш расположен рядом с заголовком, нажимается и открывает компактный редактор. Не возвращать отдельную большую кнопку «Изменить» и не переделывать остальную карточку.
- Подпись стоимости — «Стоимость за месяц», без слова «исторический».
- Значение способа оплаты сохраняется отдельно и не требует пересохранения других данных клиента.

### 2. Загрузка документов и оплата без документов

- Галочка называется **«Оплата без документов»** — не «Оплата на карту». Она должна подходить для PayPal, карты и других способов оплаты без PDF.
- Если пользователь отправил форму обычного документа без PDF, карточка клиента остаётся открытой, секция «Загрузить документ» раскрыта, а сообщение «Выберите PDF» показывается непосредственно под полем PDF.
- При ошибке сохраняются введённые поля, галочки типов документов, сумма, валюта, комментарий, срок передачи и выбранный период. Никакая запись не создаётся.
- Ошибка неправильного/невалидного PDF также должна отображаться внутри той же карточки.
- В коде `app/documents.php` и тесте `tests/http_e2e.py` уже есть реализация/регрессия этого сценария. Сначала проверь, что это действительно присутствует в актуальном `main`/ `deploy` и работает на сайте; не переписывай то, что уже исправлено.
- При создании нового документа/оплаты валюта по умолчанию должна наследоваться от текущих действующих условий клиента (например, RUB для клиента с расчётами в RUB). Остальные валюты остаются доступны. В коде уже есть получение валюты из активных условий; проверь и форму создания документа, и форму отдельной оплаты, а не только один сценарий.

### 3. Вёрстка «Изменить» у существующего документа

На скриншоте в карточке клиента название документа и/или форма редактирования сжимались до узкой колонки, текст переносился по одной букве. PR #17 заявляет исправление этой проблемы. Обязательно проверь реальный интерфейс на десктопе и мобильной ширине: название должно переноситься по словам, поля и кнопки должны иметь нормальную ширину, никакие блоки не должны схлопываться. Если проблема остаётся — исправь только CSS/раскладку этой формы.

### 4. Цвета статусов клиента

Ожидаемая схема владельца:
- **Зелёный** — «Выполнено» / оплачено.
- **Серый** — требуется подготовить/отправить документы.
- **Красный** — «Ждём оплату», особенно просроченная оплата.

В `app/ledger.php` классы статусов уже возвращаются как `good`, `warning` и `danger`; CSS/рендер на реальном сайте всё равно надо проверить. Если «Ждём оплату» отображается серым, проверь, что актуальная версия действительно развернута и CSS-класс не переопределяется. Не меняй бизнес-логику расчёта статуса без доказанной причины.

### 5. «Привязать к старому периоду (необязательно)»

Это поле нужно, чтобы прикрепить документ/сумму к **уже существующему расчётному периоду клиента** и сохранить правильную связь с историческим расчётом и отчётностью. Оно необязательное: для разовой оплаты/документа без периода можно выбрать «Без периода».

- В `app/documents.php` список строится из сохранённых `billing_periods` конкретного клиента.
- Если у клиента ещё нет сохранённых периодов, единственный пункт «Без периода» — ожидаемое поведение, не поломка.
- Если у клиента уже есть периоды, но они не отображаются, это дефект: выясни, почему связь с `engagements`/периодами не попадает в список.
- Проверяй только на существующем клиенте, у которого периоды точно есть. Не создавай фиктивные периоды и не изменяй реальные финансовые записи ради теста.
