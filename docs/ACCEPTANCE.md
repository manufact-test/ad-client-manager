**Дополнительная автоматическая регрессия (21.10.2026):** при досрочном архивировании сокращённый период делает связанные финансовые PDF устаревшими; неизменённые периоды не затрагиваются. Замена PDF предзаполняет прежние метки, период и срок передачи. Сверка SHA-256 запрещает скачивание/передачу отсутствующего или повреждённого файла. Улучшены видимость клавиатурного фокуса и узкая сетка форм; **ручная проверка мобильных браузеров остаётся НЕ ПРОВЕРЕНО**.

**Защита от повторных операций (21.10.2026):** каждая форма «Оплата / возврат» имеет неповторяющийся 64-символьный ключ, а MySQL — уникальное ограничение `payment_events.submission_key`. Повторная отправка идентичного запроса возвращает успешный результат без второго платежа и события аудита; попытка повторно использовать ключ с изменёнными данными отклоняется. Рядом проверяются отказы при отсутствии ключа, восстановление прежней схемы через идемпотентную миграцию, повторная передача документа и повторное аннулирование уже устаревшего PDF. Старые исторические записи сохраняют `NULL` в новом поле. Регрессионные PHP+HTTP тесты автоматизированы; реальная браузерная проверка остаётся **НЕ ПРОВЕРЕНО**.

**Конфликты старых вкладок (21.10.2026):** автоматический следующий период имеет уникальный серверно проверяемый ключ `billing_periods.creation_key` и снимок предыдущей границы. Повтор одного POST не добавляет лишний месяц и аудит; другая устаревшая вкладка отвергается. Создание после пометки `is_final` блокируется. Изменение или аннулирование строки начисления требует хэш-снимок прежних данных; старая форма не может затереть новую запись. Добавлены регрессии MySQL/HTTP/интеграции. **Нагрузочная браузерная проверка реально параллельных вкладок вручную НЕ ПРОВЕРЕНО.**
