**Дополнительная автоматическая регрессия (21.10.2026):** при досрочном архивировании сокращённый период делает связанные финансовые PDF устаревшими; неизменённые периоды не затрагиваются. Замена PDF предзаполняет прежние метки, период и срок передачи. Сверка SHA-256 запрещает скачивание/передачу отсутствующего или повреждённого файла. Улучшены видимость клавиатурного фокуса и узкая сетка форм; **ручная проверка мобильных браузеров остаётся НЕ ПРОВЕРЕНО**.

**Важно:** HTTP-тесты запускаются на встроенном PHP-сервере и изолированной MySQL GitHub Actions, а не на настоящем Hostinger. Они не заменяют ручной тест интерфейса мышью, клавиатурой и телефоном.

## Остаётся обязательно проверить вручную до релиза

- **Полный рабочий маршрут** с вымышленными данными в отдельной тестовой инсталляции: директор → сотрудник → реальный и демо-клиент → договор → период → 2+ работы → 2 частичных платежа → возврат → спецификация/счёт/акт (в т.ч. один многоцелевой PDF) → передача → исправление суммы → устаревший PDF → замена директором → повторная передача → архив → возвращение → удаление демо и очистка PDF → сопоставление аналитики с расчётом вручную.
- **Проверка ошибок:** чужой документ, старая вкладка после деактивации/смены пароля, одновременные операции, ошибочные даты и нулевые суммы, удалённый PDF, загрузка большого/не-PDF, CSV с повтором, Excel-инъекция, превышение размера CSV.
- **UX и доступность:** desktop/mobile, Brave/Chrome/Firefox, компактность боковой карточки, навигация с клавиатуры, контраст, формы и длинные списки, понятная обратная связь об ошибках. Не считать эту работу выполненной только по HTTP-тестам.
- **Старые данные:** определить фактические колонки прежней таблицы и реализовать согласованное сопоставление; нынешний импорт принимает **только** `docs/history-import-template.csv`-формат и требует подтверждения. До приватизации репозитория никаких настоящих таблиц/клиентов/документов не загружать.
- **Резервная копия на Hostinger:** исключительно отдельная тестовая база, отдельная приватная папка, контроль хэшей; `docs/RECOVERY.md`. Настоящую БД и рабочие файлы не трогать. Проверить восстановление и возврат.
- **Безопасность и деплой:** полный аудит публичной истории на секреты/данные, закрытый доступ к конфигу и PDF, подтверждение GitHub **Private**, повторный CI на новой видимости, проверка Auto-deploy и GitHub Actions quota, только затем интеграция и выпуск. Откат должен быть документирован и проверен.

## Правило принятия

1. Нет критичных замечаний ручного приёмочного маршрута и UX.
2. Все CI на финальном SHA **SUCCESS**; деплой из PR **SKIPPED**.
3. Изолированное восстановление на Hostinger проверено безопасно.
4. Только после завершения разработки — GitHub переведён в **Private**; история проверена на секреты/данные; CI и развёртывание повторно проверены.
5. Реальные клиенты и финансовые документы разрешены **лишь после всех предыдущих пунктов**.

Если пункт не подтверждён фактическим тестом — сохранять статус **НЕ ПРОВЕРЕНО**, а не считать «готово».
