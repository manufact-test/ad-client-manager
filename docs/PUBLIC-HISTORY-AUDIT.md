## Чего эта проверка НЕ гарантирует

Это эвристический поиск по **доступным diff patches** и текстовым файлам. Он не охватывает полностью потерянные/переписанные ветки, форки, закрытые/истекшие workflow artifacts, внешние кэши, GitHub лог, ссылки на внешние выгрузки и значения секретов с нестандартными шаблонами. Он не доказывает отсутствия всех персональных данных: имена/финансовые суммы сами по себе неотличимы от вымышленных по регулярному выражению. Нельзя утверждать, будто весь публичный след очищен.

## Финальный обязательный Gate D (НЕ ПРОЙДЕН)

1. После завершения ручной приёмки повторить скан **всех доступных refs/tags**, вложений Issue/PR, GitHub Actions logs/artifacts, фикстур и истории на чувствительные данные, включая ручной смысловой осмотр.
2. Если обнаружен секрет — **отозвать/перевыпустить его**; изменение PUBLIC на PRIVATE не отменяет прежнее раскрытие.
3. Перевести репозиторий в **PRIVATE** с подтверждением владельца, проверить доступы участников и GitHub Actions тариф/лимиты, выполнить свежий CI.
4. Убедиться, что push в `main` не публикует; сверить `deploy` до и после и Hostinger Auto-deploy. Не выполнять ручной выпуск без отдельного одобрения.
5. Только после B/C/D и согласованного release разрешать настоящие клиентские данные и документы.

**Итог:** предварительная read-only ревизия **без обнаруженных совпадений по проверенным правилам**; окончательный аудит/приватизация/выпуск остаются **НЕ ПРОВЕРЕНО**.
