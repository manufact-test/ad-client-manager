# Ad Client Manager — массовое распределение в «Контроле»

**Дата:** 22 октября 2026. **Ветка:** `feature/integrated-client-workflow`. Функциональный код: `ce1542b7a5edded52dd5c1e36c114014c8180244`. Готовность остаётся **87%**, не выпускать на Hostinger без разрешённых ворот.

## Задача и результат
В разделе «Контроль» директор видит просроченные и будущие расчётные события клиента, фильтрует по типу/сроку/демо и теперь также по состоянию поручения. Для неназначенных событий доступна галочка «В общий список». Отметьте несколько событий на видимой странице, выберите одного активного сотрудника в верхней форме и нажмите «Назначить выбранные поручения». До 60 событий за раз; уже назначенные строки не получают галочку повторно. Можно также поручить один пункт из его строки.

После назначения у события видно «В работе: имя»; директор может перейти к общему календарю, переназначить, изменить или отменить поручение. Сотрудник видит назначенное в «Моих задачах» и завершает его, но не может изменять чужие личные задачи и раздавать поручения.

## Важные инварианты
- Массив выбранных событий сервер проверяет заново по текущему списку. Поддельные/устаревшие идентификаторы, неактивный исполнитель, отсутствие роли директора и дубликат уже активного события отклоняются **без частичного сохранения**.
- Источник идентифицируется по `client_id:kind:date` — это существующая гранулярность напоминаний. Если несколько PDF одного клиента имеют один и тот же тип события и дату, они отражаются одним поручением: сервер не может разделить их без отдельной идентичности документа.
- Аудит `assign_team_task` с источником `control`; завершение или отмена сохраняют историю. Счёт, акт, PDF и деньги **не меняются** от установки/выполнения поручения. После завершения старое невыполненное клиентское событие может снова появиться «Без исполнителя» и допускает новое поручение — фактическое закрытие документа нужно выполнить в карточке.
- Нет новых таблиц, DDL, автоматических писем, переносов на Hostinger и публикации. Код только в feature, GitHub остаётся PUBLIC, реальные материалы запрещены.

## Минимальная приёмка с вымышленными данными
1. Директор: выбрать два разных вычисленных пункта, назначить их одному сотруднику одним POST; убедиться, что оба отображаются в его календаре и на доске показан исполнитель.
2. С фильтром «Уже поручено» увидеть эти строки, с «Без исполнителя» убедиться, что их там нет; проверить следующую страницу через пагинацию с сохранением фильтра.
3. Попытаться назначить уже открытый пункт второму сотруднику — должна появиться ошибка, второе поручение не создаётся.
4. Сотрудник: видит свой список и названного исполнителя, но не получает формы массового и одиночного назначения. Завершение личной задачи не закрывает PDF/договор автоматически.
5. Директор: отменить делегированную задачу; событие снова доступно для назначения без удаления записей аудита. Проверить непрерывность общего календаря и приватность посторонних личных задач.
