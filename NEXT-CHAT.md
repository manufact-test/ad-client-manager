## Что решили в последнем разговоре

1. Собственные логины (email+пароль) для директора и сотрудников, роли задаются сервером; регистрация только по действию директора/одноразовому приглашению; директор может всё, сотрудники ведут клиентов, оплаты, корректировки и аналитику, но не исходные файлы документов.
2. Личный календарь задач **у каждого**: название, дата, флаг ежемесячного повторения; выполненная повторяющаяся задача переходит на следующий месяц. Личные задачи изолированы между пользователями. Общие документные задания независимы.
3. Источник прихода и повторного клиента фиксировать отдельно, старого клиента выбирать из системы либо вводить прежнее название вручную.
4. Не раздувать CRM — компактный интерфейс и минимальное число полей.

## Ближайшее действие

**Начать технический фундамент:** безопасная конфигурация MySQL на Hostinger вне webroot, миграции, закрытая первая инициализация директора, затем вход/права и личные задачи. Сначала определить безопасный способ единственного ручного создания конфигурации без пароля в чате. НЕ ставить секреты в публичный GitHub и НЕ публиковать незащищённые админские/DB health endpoints.

## Критические напоминания

- GitHub **Public только временно** по решению пользователя; **перед реальными данными перевести в Private**. Отдельно убедиться, что секреты не попадали в историю.
- `deploy` — живой сайт. В `main` работать через CI, не публиковать сырой код или приватные файлы.
- В Hostinger есть другие проекты/Cron Jobs: не менять их.
- Документация обновляется по контрольным точкам, а не после каждого небольшого изменения.
