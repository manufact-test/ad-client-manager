## Текущее решение после UX-проверки 21.10.2026

- Пользователь проверил нынешний экран и справедливо отклонил его как преждевременную заготовку: стрелки выбора месяца и отметка «Выполнено» в списке противоречат согласованным простым задачам; редактирования карандашом нет.
- Отдельная карточка «Демо-клиенты» и показатель «Реальных клиентов в аналитике: 0» бессмысленны без обычных клиентов, счетов, оплат и полноценных аналитических выборок. Такой тест нельзя считать проверкой демо-изоляции.
- Решение: не делать точечный косметический ремонт в действующем интерфейсе и не просить повторных тестов сырого экрана. Новая рабочая ветка **`feature/integrated-client-workflow`**, в ней сначала сделать единый раздел обычных+демо-клиентов, документы/суммы/платежи, настоящие показатели; переделать задачи в единую хронологическую ленту с редактированием, без стрелок по месяцам; после этого end-to-end тесты и публикация.
- **Не менять реальную Hostinger MySQL в ходе разработки ветки:** тестировать в изолированной CI/MySQL. Не вводить реальные данные до завершения всей первой версии, полного тестирования и перевода репозитория в Private.
- Пользователь пока **не просил** делать первое сообщение для нового чата: продолжать текущую разработку и обновлять короткую документацию по существенным контрольным точкам.

## Согласованные новые требования

1. У каждого пользователя личные простые задачи: название, дата, ежемесячное повторение; задачи других пользователей не видны.
2. Директор может всё; сотрудники могут вести клиентов и финансы и видеть аналитику, но не загружают/заменяют/удаляют исходные документы, не управляют пользователями.
3. Повторные клиенты выбирают прошлую запись из списка или «Другое» с прежним названием вручную; отдельно источник привлечения.
4. **Демонстрационный клиент**: отдельная отметка «Демо» при создании; тестовые суммы, оплаты и месяцы исключаются из *всех* реальных аналитических показателей. Директор может полностью удалить демо и все связанные тестовые записи/документы. База и первоначальный интерфейс демо подготовлены; полный функционал счетов/документов ещё предстоит.
5. Порядок запуска: полный продукт → все тесты на выдуманных данных → GitHub Private и повторная проверка деплоя/безопасности → импорт реальных клиентов и пробная эксплуатация сотрудниками.

## Риски и ограничения

- GitHub пока **Public** по решению пользователя: только код и фиктивные значения, без секретов, PDF и данных клиентов. Обязательный переход в **Private перед внесением настоящих клиентов**, а не просто в любой отдалённый срок.

- Автодеплой может менять страницу при коммитах — сначала CI, проверка доступности и авторизации.
