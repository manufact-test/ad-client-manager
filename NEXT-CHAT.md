## 2. Что реализовано: не переделывать заново

- PHP 8.3+/MySQL 8, центральная CSRF и session-password binding, 30-минутный idle/12-часовой абсолютный срок входа; директор и сотрудник, временные пароли, обязательная смена, отзыв других сессий после смены/сброса, отключение сотрудника. Приватная регистрация директора, rate limiting.
- Одна форма для реального и демо-клиента; имя, рекламные платформы, источник, повторное сотрудничество/архив, поиск по клиенту/площадке, demo-фильтры, боковая карточка. Демо исключён из всей реальной аналитики.
- Пред-/постоплата, якорь дня 1–31, расчётные непересекающиеся периоды, закрытие и возобновление, три категории работ, редактирование/аннулирование, частичные оплаты и возвраты.
- PDF только вне public_html, несколько меток у одного файла (договор/счёт/акт/спецификация); загрузка/замена/удаление директором, передача сотрудником, финансово устаревший PDF заблокирован до замены. Безопасные скачать/роли/CSRF.
- Личные задачи по срокам с редактированием, удалением, выполнением и ежемесячным повтором; вычисляемые напоминания о подготовке/передаче документов; директорский журнал изменений.
- Аналитика с точными целыми копейками/центами, отдельными валютами, помесячными категориями, возвратами, LTV, архивом/источниками. **Новый крупный блок:** `app/export.php`: URL `/?export=balances` (реальные клиенты: финансовая сверка, без демо) и `/?export=client&client_id=N` (детальная история одного клиента, включая непривязанные к периодам операции, демонстрационная метка). Скачивание после входа, CSV UTF-8 BOM/semicolon, Excel-formula escape, сохранение точных сумм, возвраты показаны отрицательными движениями. Кнопки в аналитике и карточке. Существующие операции экспорта не изменяют БД.
- Только директорский двухэтапный импорт канонического CSV (preview / confirm, hash-idempotency, SQL transaction, строгая структура и размер). `docs/history-import-template.csv` — **фиктивный пример**; реальный старый Excel-прайс/таблица не предоставлен, сопоставление настоящих колонок НЕ сделано.
- GitHub Actions тестируют PHP/MySQL, HTTP логины/CSRF/задачи/CSV/PDF/архив, импорт, экспорт, Exact-cent и реальное **изолированное** восстановление SQL+PDF в другую CI-БД. **Hostinger restore НЕ проверен.**

## 4. Что делать первыми крупными блоками в новом чате

1. Подключить GitHub; получить **актуальные** HEAD feature/main/deploy, статус PR Draft и последнюю GitHub Actions. Если CI не SUCCESS, начать с диагностики и исправления, а не с нового функционала.
2. Продолжить **полную функциональную и UX-приёмку на вымышленных данных**: клиент → архив/повтор → 2+ работы → платежи/возврат → документы → передача → изменение сумм → замена PDF → повторная передача → аналитика → выгрузка. Проверить сложные случаи, права, mobile/accessibility и взаимодействие через настоящие HTTP/браузерные сценарии (CI curl — не полноценный браузерный тест).
3. Провести ревизию сохранности: одновременные записи, обрыв загрузки PDF, ошибки файлового хранилища/DB transaction, полнота финансовой истории и корректность аудит-следов. Исправить и добавить регрессии по фактам.
4. **Когда будет безопасно и будет известна структура старых данных**, расширить импорт до согласованного сопоставления колонок Excel/CSV; не просить настоящую историю и клиентские сведения в публичный репозиторий.
5. Позже, после завершения функциональности и изолированных тестов — проверить отдельно безопасный Hostinger recovery/rollback по `docs/RECOVERY.md`. **Не трогать живую БД/сайт без релизного плана.**
6. Завершить релизные шаги из `docs/ACCEPTANCE.md`: ручная приёмка, аудит приватности, перевод GitHub в **PRIVATE** перед реальными данными, повторная проверка CI/CD, деплой и только затем реальные клиенты.
