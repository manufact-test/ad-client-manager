## 3. Последний крупный этап: запрет неожиданного деплоя

Файлы:
- `.github/workflows/ci-deploy.yml` — push в `main` выполняет verify, **НЕ** деплоит. Деплой разрешён только если `github.event_name == 'workflow_dispatch'`, `github.ref == 'refs/heads/main'`, `inputs.confirm_release == 'YES'`, и verify успешен. Деплой только `index.php`, `.htaccess`, `app/` из `main` в `deploy`. До ручного запуска все PR checks показывают publish SKIPPED.
- `tests/release_policy.py` — static CI-проверка, что push больше не может незаметно публиковать и условия ручного выпуска не ослаблены.
- `scripts/release_preflight.php [--verify-pdfs]` — read-only CLI диагностика PHP, приватного конфига, БД, 11 таблиц, индексов новой защиты, изолированной папки документов, активного директора и SHA-256 PDF. `scripts/.htaccess` блокирует веб-доступ. Скрипт не переносится на Hostinger обычным деплоем; запускать только на доверенной изолированной копии. **Он НЕ выполняет миграций и НЕ доказывает готовность продакшена.**
- `tests/preflight_fixture.php` — проверка, что в одноразовой CI-БД валидный PDF проходит preflight, повреждённый проваливается, затем fixture очищается.
- `docs/RELEASE.md` — полный регламент ворот A–D, точный пример проверки реального/демо, финансов, PDF, прав, восстановления, приватизации и будущего ручного выпуска.
